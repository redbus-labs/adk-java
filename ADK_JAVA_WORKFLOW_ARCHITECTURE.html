1. Core Architectural Shift: BaseAgent as BaseNode

Key Architectural Insight: In ADK Java 1.12+, BaseAgent extends BaseNode, which implements the Node interface. This foundational shift unifies standalone agents and graph execution nodes into a single, uniform type hierarchy.
Unified Concept

Agents Are Workflow Nodes

Every LlmAgent, custom agent, or sub-agent is natively a Node. You can execute any agent standalone via Runner or plug it directly into a complex directed graph without writing wrappers or adapters.

Recursive Composability

Workflows Are Nodes Too

Workflow extends BaseNode. A complete workflow graph is itself a Node. This enables sub-workflows inside workflows to arbitrary depth with clean encapsulation.

Reactive Streaming

RxJava Event Pipeline

Node execution is driven by RxJava 3 Flowable<?> streams, allowing async, non-blocking execution, streaming tool output, partial tokens, and backpressure handling.

2. Key Workflow Graph Components

Node & BaseNode

Defines units of work within a workflow graph. Supports input/output/state schemas, timeouts, retry configurations, and rerun controls on session resume.

Graph & Edge

Represents the directed acyclic or cyclic execution graph. Edges connect predecessor nodes to successor nodes with deterministic scheduling.

EdgesBuilder

Provides a fluent DSL for building workflow connections: edges.from(start).to(researcher).from(researcher).to(writer).

Start

Special entry node designating the initial entry point of a workflow graph.

JoinNode

Fan-in synchronization node that waits for all predecessor nodes to complete before executing, collecting outputs as a map keyed by node name.

NodeRunner

Orchestrates execution of individual nodes or sub-graphs, managing state transitions, events, and invocation context.

5. Easy Migration & Adaptation Guide

Adapting existing ADK agents to Workflow Graphs requires zero changes to agent class definitions.

Building a Workflow Graph in Java

// 1. Create your standard ADK agents (no code changes needed!)
LlmAgent researchAgent = LlmAgent.builder()
    .name("ResearchAgent")
    .model("gemini-2.5-flash")
    .instruction("Research topic and provide findings.")
    .build();

LlmAgent writerAgent = LlmAgent.builder()
    .name("WriterAgent")
    .model("gemini-2.5-pro")
    .instruction("Summarize research findings into a polished report.")
    .build();

// 2. Build the workflow graph using EdgesBuilder
Workflow researchWorkflow = Workflow.builder()
    .name("ResearchAndWriteWorkflow")
    .description("Multi-step research and writing workflow")
    .addEdges(edges -> edges
        .from(Start.INSTANCE).to(researchAgent)
        .from(researchAgent).to(writerAgent))
    .build();

// 3. Execute the workflow via Runner or NodeRunner
Runner runner = Runner.builder()
    .agent(researchWorkflow)
    .sessionService(sessionService)
    .build();

runner.runAsync("my-app", "user-123", "Write a summary on quantum computing")
    .blockingSubscribe(event -> System.out.println(event));

Parallel Processing with Fan-In Join

JoinNode joinNode = JoinNode.builder()
    .name("SyncBarrier")
    .build();

Workflow parallelWorkflow = Workflow.builder()
    .name("ParallelAnalysisWorkflow")
    .addEdges(edges -> edges
        .from(Start.INSTANCE).to(researchAgent)
        .from(Start.INSTANCE).to(dataAgent)
        .from(researchAgent).to(joinNode)
        .from(dataAgent).to(joinNode)
        .from(joinNode).to(writerAgent))
    .build();

6. Architectural Concerns & Best Practices

Deterministic Scheduling

Node scheduling order in Graph is strictly deterministic based on edge declaration order. This guarantees reproducible execution across environments.

Resilience & Retry Policies

Each node supports a custom NodeConfig with RetryConfig for exponential backoff, maximum retry attempts, and execution timeout limits.

State Isolation & Concurrency

Session state is synchronized across node boundaries. Parallel nodes operate on immutable snapshots or synchronized maps to prevent state corruption.

Hot Reloading & Registry

Workflows registered via ComponentRegistry work seamlessly with ADK Dev Web Server hot-reloading for rapid interactive debugging.
